# 群聊协议

模型只收到聊天数据和回复协议。应用不向模型注入节奏参数、触发原因、截止时间、退避状态、内部片段编号、参与率或调度统计。直接 @ 的回复义务在新会话的 system 中统一说明；不逐批次注入 developer 待回复要求，不再注入参与度提示。回复纠错仍按需注入。

## 授权与配置

入口授权、逐群触发参数及管理权限见 [配置与权限](configuration.md)。群 slash command 仍需 @ bot，普通消息无须 @。

## 消息历史与触发

非系统群消息按到达顺序持久保存，包含消息 ID、发送者、时间、按原顺序排列的文本/@/图片索引/占位、引用。发给模型的记录及引用不包含 `time_source`；`time` 使用系统当前时区，精确到秒，不带时区后缀，时区仅在 developer 提示词中统一说明。时间点取事件原值，缺失时使用接收时间；引用原时间不可取得时 `time` 为 `null`，不伪造。名称优先群名片、QQ 昵称，再 QQ 号。@ 表示为 `@(qqid)nickname`，包括 bot；全体成员单独表示。

聊天历史与待处理候选分开：普通消息只在配置的有效期内具有主动参与资格，过期不表示已经提交，也不立即删除聊天记录。默认有效期及配置约束见 [配置与权限](configuration.md)。已经提交的任务不因消息过期取消。

有效外部消息先短时合并。距上一条有效消息超过 30 秒或无历史时等待 2 秒，否则等待 5 秒；同人续发等待 2 秒，换人等待 0.5 秒，整批从首条接收起最多等待 8 秒。普通裸图开批至少等待 4 秒。已到期的窗口不因后来消息重新延长，预处理耗时计入等待；这些上限不保证模型响应耗时。

直接 @ bot、引用 bot 消息最多合并等待 1 秒，绕过普通观察间隔和沉默退避。只有直接 @ 产生必须回复非空文本的义务；引用 bot 仍可沉默。义务汇总本批全部新消息，背景和引用中的旧 @ 不产生义务。这两类直接互动不按普通消息有效期丢弃；即使内容仅为表情或不支持的消息，也保留此触发例外。

普通观察等待合并完成、配置的观察最小间隔及沉默退避均结束，再提交仍有效的新消息。普通观察间隔从实际提交计算；单条消息也可获得观察机会，不再累计条数触发。消息到达安排的一次性定时处理可在群友停止发言后运行；没有有效候选时不调用模型，同一批已处理消息不重复观察。

连续两次成功完成且没有聊天输出的普通观察后开始退避，等待依次为 60、120、240、300 秒，之后保持 300 秒；从该轮结束计算，与普通观察间隔取较晚者。成功完成且实际交付聊天文本、表情或图片后清零；直接互动沉默不增加退避，失败、取消和超时不计沉默。命令回复、等待提醒、错误通知不算聊天输出。

有效外部消息间隔超过配置的片段间隔时，下一条消息开始新片段，旧普通候选失去触发资格，旧退避清零。时间边界不保证语义话题一致，模型仍根据内容判断是否接话。继续使用原群 thread，不因片段切换创建新会话。

模型输入的 `messages` 只包含本批新提交的待处理消息；`background` 保留为空，不再自动补入历史窗口。已经提交或提交结果未知的记录不进入后续批次，过期或取消的普通候选也不补入背景；旧 thread 中已有历史不会自动删除。引用目标若在同一冻结批次的 messages 中，只携带 message_id；否则展开原内容，可跨片段，不递归展开。显式引用可包含已提交的旧消息，但不授权补答或重做旧请求。系统引用始终使用占位。

群消息分为三类：

- 系统：用户输入的有效应用命令（包括参数或权限失败）及应用用 bot 发送的命令结果、提醒、错误通知。正文不进入历史或模型；引用仅显示 `<redacted system message>`。无法确认来源的 bot 自身上报先按系统处理，取得 agent 发送回执后才进入低优先历史。
- 低优先：纯表情、不支持的消息类型及全部 agent 自身消息。不创建或延长窗口，不推进普通片段、观察间隔或退避，不唤醒失败批次。不可读内容只记录占位，例如 `[转发的消息，暂不支持读取]`。
- 普通：外部非空文本、普通图片及含这些内容的混合消息，保留原有触发逻辑。混合消息同时保留表情和不可读占位。

待提交低优先消息最多积压 14 天；下一次普通消息或直接互动触发时，将冻结前已到达的全部积压按到达顺序加入新消息，可跨片段，提交后不再补入后续批次。仅剩低优先积压且没有直接互动时不调用模型，包括普通候选过期后的情况。发送回执和自身上报按群及消息 ID 去重。

提交前冻结输入快照，重试使用相同内容。同群忙碌时，直接互动通过 user steering 追加，普通消息等待当前任务结束后重新检查时效；总结和压缩期间继续记录，结束后重新判断。冻结的普通批次若提交前包含过期候选，则整批过期，避免重试时改写已冻结输入；其中明确未提交的低优先积压释放，留给下一批。

明确未提交的失败批次保留，等待后续普通消息或直接互动重新检查，不无限定时重试；提交结果未知不自动重发。重启只恢复明确未提交状态，等待普通消息或直接互动唤醒后先过期再调度，不重跑进行中的任务或补答旧讨论。

## JSON 回复与纠错

每条完整 assistant 消息（包括过程说明）必须只包含一个 JSON 对象：

```json
{"response":"你好呀","sticker":"开心"}
```

`response` 必填，只允许字符串或 null。`sticker` 必须是配置键字符串；模型仅收到可选名称列表，按语境和情绪选择，不获知各名称是否对应图片。有文本必须填写 sticker；无文本可省略 sticker。应用负责匹配图片，配置值为 null 时跳过表情，不作为回复错误；需要传达的内容应放入 response，不能依赖表情一定发出。可选 `quote` 为消息 ID 字符串或 null，必须是本群可见历史中的消息（包括已展开引用），不能是系统、未知或跨群消息。有文本时仅引用文本首段；没有文本时引用实际发送的表情。无文本且省略 sticker 时不能带非空 quote；选择了合法名称但无对应图片时，合法引用随表情一起跳过。引用校验在发送前完成，失败使用同一纠错流程。空白文本按无文本处理。未知/重复字段、错误类型、代码围栏和多个 JSON 对象均无效。

```json
{"response":null}
{"response":""}
{"response":null,"sticker":"开心"}
{"response":"你好","sticker":"平静"}
```

前两例沉默；第三例在应用配置有对应图片时只发表情，否则不发送消息；当配置 `平静: null` 时第四例只发文本。整条通过校验后先发表情，再发文本；不发送原始 JSON。不提供 send_sticker 工具或每 turn 一次额度；普通图片仍用 send_image 工具。

@ 批次提交后，下一条有效 JSON 必须含非空文本；文本成功交付后解除义务，新的 @ 再次设置。只发表情、图片工具交付或沉默不能满足该义务。

格式或必回复校验失败时，不发送原文，连续错误数 +1：前两次注入 developer 纠错，第三次发送一次“agent 回复解析失败”并结束纠错、停止仍活动的 turn。任一合法输出，包括允许的沉默，计数归零。turn 结束仍未履行回复义务或纠错续接没有有效输出，也按失败处理。错误计数跨纠错续接保留；纠错不延长任务期限。工具、网络及发送结果未知不是 JSON 错误，不重放已发送的表情或文本。

## 图片和提醒

QQ 内置表情（`face`）在群历史中按原位置显示为 `[qqface:ID:名称]`，例如 `[qqface:178:斜眼笑]`；未知 ID 显示为 `[qqface:ID:未知表情]`，不丢弃消息。它与图片形式的 `sticker_id` 分开，不需看图工具。纯内置表情属于低优先，文字与表情混排仍按普通文字处理，直接互动保留原有触发例外。含内置表情的消息不作为 slash command。

群回复的 `response` 可包含已知内置表情标记，应用按原顺序转换成文字和 `face` 消息段；`sticker` 仍按既有协议填写。普通文字 `xyx`、`/xyx`、`[斜眼笑]` 不转换。标记缺损、ID 未知或名称不匹配时，整条回复在发送任何表情或文本前进入现有纠错流程。仅含内置表情不能满足直接 @ 的文字回复义务。长回复按 1500 个字符或内置表情拆分，表情视作一个单位，不拆开标记，引用仅附在首段。应用系统通知和私聊不解析此标记。发送支持范围以应用随包映射为准，须与部署的 NapCat 版本匹配。

普通图片在历史中保留 `image_id`，图片形式表情保留 `sticker_id`。同群相同 QQ 资源标识复用同一个 ID，跨群隔离；两种媒体类型也可共享资源 ID。优先使用 file_unique，否则使用 file 资源标识；不同 QQ 标识但内容相同的图片不保证去重。保留按需下载，重复到达更新来源并复用已有缓存，不主动下载、不直接插入 user 上下文。图片和表情均将 ID 值传给 `qq_image.view_image(image_id)`，它校验当前群和活动任务 token，下载原文件到工作区并返回 MCP 图片预览和相对路径。动画预览首帧，原文件保留动画。保留现有 10 MiB 下载限制、格式/URL/工作区路径检查。过期、跨群或缺失索引明确报错。

首次成功发送 JSON 对应文本或表情后开始计时；此 turn 之后每条完整 assistant 消息重置计时，包括沉默和无效输出。每段等待在 30 秒、5 分钟各发送一次提醒，turn 结束取消。沉默 turn 不提醒，不发送“任务完成”兜底。不发送 OK 表情、记忆写入及自动压缩提示，显式命令保留操作结果。自主任务尚未发言时普通故障只记日志；待回复 @ 或已发言时可发送简短失败反馈。解析熔断始终发送规定提示。

## 会话与保留

`/stop`、`/new` 清除命令到达时尚未提交的任务及对应定时处理，命令后到达的消息继续调度；总结和压缩期间记录消息，结束后重新检查时效。具体命令见 [会话与命令](sessions.md)。

每日清理超过 14 天的已处理、已过期或未提交低优先消息内容及过期图片；仍待处理的直接互动保留。断线漏报不补抓，失效图片和删除引用不能保证恢复；不提供转发展开、离线补抓、永久聊天归档或对触发机制的绝对保密保证。

旧版本配置和状态的升级操作见 [部署与迁移](../internal/deployment.md)。
