# QQ Codex Agent

部署在树莓派上的个人 QQ AI 助手，通过 NapCat OneBot 11 连接 QQ，使用本地 Codex app-server 和 ChatGPT 登录。

支持自然语言问答、图片理解、图片生成和代码执行；读取运行时 AGENTS.md 定制提示词，使用 Approve for me 自动审批及受限文件系统。

- 私聊通过 `private_users` 授权；配置中的群允许全员参与，无须 @。群命令仍需 @ bot，群设定修改和群记忆清除默认限群主、管理员。
- 群消息按到达顺序持久化，直接 @、引用 bot、距上次请求 60 分钟或累计 20 条消息时提交积压历史。后两项逐群配置；无人发消息时不主动唤醒。不可读消息记录占位并计数，自身不触发。
- 每条群 assistant 消息必须为 JSON，按协议选择沉默、表情或文本。@ 后下一条有效回复必须有文本。连续三次解析失败熔断；错误不发送原文，纠错使用 developer 消息且不延长任务期限。
- 图片只进入群历史索引；`qq_image.view_image(image_id)` 按需下载原图并返回预览。生成图仍通过 `list_images` 查询、`send_image` 交付，支持用 Pillow 制作 GIF。
- 参与率从启用以来累计，按实际 QQ 消息计数，跨重启和 `/new` 保留。低于 `1/(群人数 * participation_ratio)` 时提示模型适当参与，ratio 默认 5.0。
- 首次成功发送 JSON 回复后才开始 30 秒/5 分钟提醒计时；下一条完整 assistant 消息重置计时，turn 结束取消。不发送 OK、记忆写入或自动压缩通知，显式命令保留回复。
- 各私聊、各群独立执行；活动 turn 通过 steering 接收消息。群聊按批次提交，发送结果未知不重放。重启只恢复未提交历史，等待外部消息触发。
- `/new` 群聊先总结后切换，`/new blank` 直接空白切换；私聊 `/new` 保持原行为。工作区、模型、群设定和记忆保留。`/stop` 清除本会话待处理任务，后续消息仍可触发。
- 保留 `/help`、`/model`、`/status`、`/compact`、`/profile`、`/prompt`、`/group-profile`；群聊 status 显示已提交消息批次。模型推理强度固定 medium。
- 私聊保持原有文本和图片输入、进度与回复。群聊引用保留发送者和原时间；缺失原时间明确标记未知。群 @ 按 `@(qqid)nickname` 呈现，包括 bot。
- 每天清理超过 14 天未访问或修改的普通文件及已消费历史；未提交群历史和累计计数保留。技能、认证及 runtime 历史不参与清理。
- 详细协议、故障语义和升级步骤见 [group-design.md](group-design.md)。

两仓库接入、提示词覆盖及部署检查见 [nix/README.md](nix/README.md)。

开发、部署、登录及排障方法见 [AGENTS.md](AGENTS.md)。公共运行时模板见 [AGENTS.runtime.md](AGENTS.runtime.md)，私聊和群聊模板分别见 [AGENTS.private.runtime.md](AGENTS.private.runtime.md) 与 [AGENTS.group.runtime.md](AGENTS.group.runtime.md)。

可选主配置 `agent_admin_qq = "123456789"` 指定单个全局 agent 管理员，接受正整数或数字字符串；缺省不提示身份，非法值阻止启动。所有新群 thread 的 system 指令说明该 QQ 的管理员身份，不增加白名单、群设定修改或工具权限；私聊不注入。修改后重新加载配置，并创建新群 thread 生效。RPi 直接在 `qq-codex-allowlist.age` 完整配置的顶层填写该字段。Nix 通过 `services.qq-codex-agent.configFile` 读取整份解密文件，不合并默认值；旧生成模式才使用 `agentAdminQQ` 选项。

成员记录保留现有 SQLite 表和字段，每人最多 500 字符，全群不做 2000 字符截断；群共同摘要最多 1000 字符，群设定单独保存。记录用于推进聊天，可保存本人明确表达的游戏、音乐、专业方向及主动提供、用于共同游戏的 Steam 公开标识；不记录真实姓名、私密联系方式、住址、证件、登录账号或凭据，不把第三方转述、玩笑或猜测写成事实，不把个人偏好推成全群共识。记录可在当前群公开查看，当前个人要求优先于旧记忆。

群聊 `/new` 会停止当前任务、清空队列，并额外调用当前 thread 的模型生成最多 2000 字符的交接摘要，只显示操作状态，不发送摘要正文。总结依据当前可见上下文，要求只归纳群成员表达及上次交接背景，不归纳 assistant 回复、工具输出、system/developer 指令或群设定；这是提示词约束，不保证角色内容绝对隔离，也不重新读取完整原始历史。摘要作为参考数据加入新 thread 的最新群提示词快照，不授权自动执行旧请求；原图不复制进摘要，文件与索引仍保留。总结最长 15 分钟（若配置的任务期限更短则取较短值）。总结期间普通消息继续积累，完成后调度已触发批次，`/stop` 可取消，`/new blank` 可取消并空白重置。失败、超时或取消时不切换、不自动重试，但总结请求可能留在旧历史中；摘要与待切换状态一并持久保存，重启后继续交接。已待切换时重复 `/new` 不重新总结，`/new blank` 清除摘要。新 thread 创建或提示词注入失败时保留摘要，未完成注入不提交用户消息。

群聊使用简短基础提示词，保留文件操作、执行、网页搜索、QQ 图片交付及记忆工具说明；私聊保持 Codex 默认基础提示词。群设定仅用于角色、语气和聊天方式，不覆盖应用权限及隐私规则。群聊模板 `AGENTS.group.runtime.md` 和群设定仅在创建 thread 时写入 `base_instructions`（Responses 请求的 system `instructions`），恢复、总结和压缩沿用已保存的 system；群模板更新、群设定设置或清除后需新建 thread 生效。bot QQ 号及群昵称由代码在新 thread 的 system 中固定注入，不依赖模板占位符。公共模板仍参与每轮 developer 快照。每个独立任务比较应用规则和记忆快照，仅在变化时通过 developer 消息注入最新应用规则和记录，保留聊天历史；按 thread 持久去重，重启后继续生效，新 thread 首次必注入。压缩完成后使去重记录失效，下次独立任务补注入一次；轮前空闲压缩则在本轮启动前补注入。群聊开启 runtime 的客户端 developer 消息保留功能，支持远程 v2 手动及自动压缩。`/new`、重启和压缩不删除数据库设定或记忆。

消息收发、任务进度及真实错误可直接查看 `sudo journalctl -u qq-codex-agent -f -o cat`。日志包含聊天正文，避免公开分享；图片二进制不记录，常见凭据字段脱敏。
